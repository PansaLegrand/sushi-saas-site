テストは「何を mock できるか」で分かれます。DB を mock したテストは unique constraint を証明できず、auth guard を mock した route test はデータ取得前の認証を証明できません。

| 階層 | 証明すること | mock 可能 |
| --- | --- | --- |
| Unit | 純粋ルールとアーキテクチャ | なし |
| API | HTTP、envelope、認証順序 | service/model、guard 以外 |
| Service | orchestration、再試行、コスト、補償 | model、外部 SDK |
| Component | ユーザーに見える挙動 | `fetch` |
| Database | 制約、lock、実 timestamp | なし |
| E2E | ログイン済み browser とローカル基盤 | なし |

全 route に 401/403 より前にデータ関数が呼ばれないことを証明する auth test が必要です。金銭・credit mutation には 2 回の同一呼び出しで 1 effect を証明する replay test が必要です。

```bash
pnpm test:fast
pnpm test:run
pnpm test:cov
pnpm test:db
pnpm exec playwright install chromium
pnpm test:e2e
```

`test:fast` は外部基盤を使わないコミット前の検証、`test:run` は設定された Vitest プロジェクトの実行です。`test:cov` はサービス、モデル、API ルート、共有サーバーコード、Admin データコードのカバレッジ下限を確認します。

`TEST_DATABASE_URL` と `TEST_REDIS_URL` がどちらも未設定なら、Vitest はテスト収集前に基盤プロジェクトを除外します。PostgreSQL と Redis はそれぞれの URL で有効になり、Redis だけの実行では Better Auth や PostgreSQL を初期化しません。CI は両方の URL を要求し、基盤がなければ失敗します。テストは表を空にするため、PostgreSQL テスト DB 名には `test` が必要です。本番にテスト URL を設定しないでください。

Playwright は login、tenant credit、Garage upload/delete、5-credit image task から worker と signed download まで検証します。

外部 E2E の接続先には `E2E_BASE_URL`、`E2E_USER_EMAIL`、`E2E_USER_PASSWORD` が必要です。書き込みテストは使い捨ての環境を `E2E_ALLOW_MUTATIONS=1` で明示した場合だけ実行します。本番を接続先にしないでください。

CI は lint、PostgreSQL 16 migration、Redis、coverage、全 build、browser flow を実行します。緑にするため threshold を下げたり、実インフラ test を mock に置き換えないでください。

## 本番成果物と性能の検査

`pnpm build` 後に `pnpm test:production` を実行します。CI は隔離した web/admin の本番成果物を起動し、モバイルログイン、静的ファイル、ヘッダー、匿名転送を検査します。実際の開発スタックのテストも残ります。`pnpm benchmark:ledger -- --check` は1,000、10,000、50,000行の合成データで CPU を測定し、本番遅延を保証しません。ESLint を直接実行し、hook 依存の問題をエラーにします。外部サービスと Studio 編集画面は別の使い捨て環境で確認してください。
