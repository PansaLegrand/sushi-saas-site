このページを終えると、スターターは**あなたのプロダクト**の名前、URL、言語、見た目で動き、各オプション機能について「維持・変更・削除」の判断が明確になります。個別画面を変更する前に決めてください。プロダクトのアイデンティティと範囲は、URL、メール、法務文書、解析、課金、管理コンソールに影響します。

## 同梱されるものと選ぶこと

| 領域 | 同梱時の動作 | あなたが決めること |
| --- | --- | --- |
| 製品 identity | `saas.config.json` が名前、slug、support、docs URL を追跡 | customizer を実行して diff を確認 |
| サポート | Support email は追跡される製品値 | 本番設定の検証で必須となる実際のサポートメールを設定 |
| 言語 | 英語、中国語、スペイン語、フランス語、日本語を利用可能。URL 接頭辞は必要な場合だけ付く | 既定の言語、提供する言語、ブラウザ言語の自動判定 |
| ビジュアル | Web と管理画面で共有するビルド時プリセットは `studio` | 維持するか、コードで `glass`、`soft`、`editorial`、`brutalist` を選ぶ |
| カラーモード | 顧客向けアプリは環境変数で `system` が既定 | `system`、`light`、`dark` を選ぶ。管理画面にはまだモード切替がない |
| 法務ページ | 既定のデータフローに沿った、草稿警告付きのひな型 | 身元情報と方針を完成させ、専門家のレビューを受ける |
| オプション機能 | 課金、ストレージ、メール、Slack、解析、紹介、タスク、予約のコードまたはアダプター | 維持して設定するか、UI・検証・ルート・文書を一緒に削除する |

## 推奨する開始点

実際のプロダクト名を設定し、情報設計が固まるまでは `system` モードと `studio` を維持し、チームが継続して管理できる言語だけを有効にするのがおすすめです。明確な目的、ユーザー向け説明、運用手順が整うまでは、アクセス解析、広告、紹介、デモ機能を無効にしておきます。

別の選択もできますが、作業が増えます。言語を増やすと対象市場と翻訳保守が増えます。強いプリセットは差別化になりますが、ライト・ダーク・管理画面の確認が必要です。既存連携の有効化は速い一方、認証情報、障害、プライバシー開示、サポートが増えます。

## アイデンティティと言語を設定する

まず Git で追跡される customizer を実行します。

```bash
pnpm customize

pnpm customize -- --name "Acme Cloud" --slug acme-cloud --preset glass --locales ja,en --default-locale ja --support-email support@example.com --docs-url https://docs.example.com --yes
```

コマンドは `saas.config.json` を検証して atomic に書き、既存の ignored profile に公開値だけを同期します。Secret は変更しません。`--dry-run` は候補表示、`--no-env` は同期停止です。本番 gate は追跡 identity と矛盾する override を拒否します。

## ビジュアルプリセットを 1 つ選ぶ

Customizer で preset を選ぶか、追跡設定を編集します。

```json
{ "appearance": { "preset": "glass" } }
```

`src/config/style.ts` は `saas.config.json` から型付き値を導出します。Web と admin は同じ preset を使い、ユーザーごとの selector ではありません。

## 法的な身元情報を完成させる

法的な身元情報は `saas.config.json` の `legal` に設定します。法人名、住所、プライバシー・法務の連絡先、準拠法、発効日が対象です。`src/config/legal.ts` はその値を読み込み、製品固有のポリシー本文と `LegalData.subProcessors` はこのファイルで編集します。必須項目が欠ける間は `LegalConfig.isConfigured` が false となり、法務ページに草稿の警告が表示されます。公開前に身元情報とポリシーの両方を確認してください。

同梱文書は起草用の骨組みであり、法律相談や完成済みポリシーではありません。使わない事業者を削除し、個人データを受け取る事業者を追加し、保持期間とアカウント削除を一致させ、資格を持つ専門家のレビューを受けてください。

## プロダクトの範囲を決める

各オプション機能について、次のいずれかを記録します。

1. **維持：**認証情報、ユーザー向け文言、監視、障害対応、責任者を設定する。
2. **変更：**既存のサービス境界の内側で方針や事業者を変え、テストと公開ガイドを更新する。
3. **削除：**ルート、UI、本番検証、ジョブ、文書を同じ変更で削除する。空の認証情報は判断ではありません。

維持する機能については、[プランと権限](/ja/docs/plans-and-entitlements)、[Stripe 課金](/ja/docs/stripe-setup)、[ファイルアップロード](/ja/docs/storage-uploads)、[デプロイとセキュリティ](/ja/docs/deployment-and-security)へ進んでください。アクセス解析を使うかどうかと同意取得の選択は、[アクセス解析と同意管理](/ja/docs/analytics-and-consent)で決めます。

## 機能開発前に検証する

```bash
pnpm config:check
pnpm config:check:prod
pnpm lint
pnpm test:run
pnpm build:web
pnpm build:admin
```

デフォルト言語に接頭辞がないこと、追加言語が解決すること、無効な言語が選択肢に出ないこと、ドキュメントとサポートのリンクが約束どおりであること、両アプリが同じプリセットを使うこと、顧客向けアプリがライトとダークの両方で読めることを確認します。プライバシーと利用規約を開き、草稿警告や方針のプレースホルダーが残る間は公開しないでください。

## まだ完成していないもの

`pnpm customize` により、Git で追跡するブランド・製品設定の手順を利用できます。実行時のプリセット選択、管理画面のダークモード、環境変数によるサポート先、法務レビュー、オプション機能の採用判断は導入チームが担当します。サポート先は `saas.config.json` の `product.supportEmail` に設定します。
