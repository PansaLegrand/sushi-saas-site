> コミット [`35e64b9`](https://github.com/PansaLegrand/sushi-saas-template/tree/35e64b91f4bb62dffea2ab928316eebc3d346cc9) で確認済みです。

まず **Core** から始めます。顧客アプリ、永続 worker、PostgreSQL、Redis、非公開のローカルオブジェクトストレージが含まれます。最初の目標はデモワークスペースにログインしてクレジット台帳を見ることです。このローカル体験には Stripe、メール、AI プロバイダーのアカウントは不要です。

## 開始する構成を選ぶ

| プロファイル | 起動するもの | 選ぶ場面 |
| --- | --- | --- |
| **Core — 最初におすすめ** | 顧客アプリ + 永続 worker | スターターの評価や製品開発を始めるとき。 |
| Operations | Core + 管理コンソール | 請求、ジョブ、顧客サポートを運用するとき。 |
| Publishing | Operations + Content Studio | 独立したコンテンツ編集アプリも必要なとき。 |

他のアプリは後から追加できます。プロファイルはローカルツールとビルド対象を選ぶもので、製品プラン、権限、利用可能な API ルートは変更しません。

## 1. 環境を準備する

- Git
- Node.js `>=24.22.1 <25`（`.nvmrc` が検証済みバージョンを指定）
- pnpm `10.22.0`
- ローカルで起動した Docker と Compose

## 2. Core を起動する

ターミナルで次のコマンドを実行します。確認済みのソースコミットからブランチを作り、コードと手順を揃えます。

```bash
git clone https://github.com/PansaLegrand/sushi-saas-template.git
cd sushi-saas-template
git switch -c my-saas 35e64b91f4bb62dffea2ab928316eebc3d346cc9
export SAAS_STARTER_PROFILE=core
pnpm starter core install
pnpm starter core setup
pnpm dev:seed
pnpm starter core doctor
pnpm starter core dev
```

ターミナルを起動したまま、[localhost:3000/login](http://localhost:3000/login) を開きます。

Setup は不足している Git 管理対象外の環境ファイルを作り、PostgreSQL、Redis、Garage を起動します。ローカルのアプリ・テスト・復元訓練用 DB を作成し、Drizzle マイグレーションを適用して非公開の `sushi-dev` bucket を準備します。Core は Content Studio のインストール、環境ファイル、DB 作成、マイグレーションを省略します。Setup は再実行でき、既存の環境ファイルを上書きしません。

`doctor` はツール、環境境界、インフラ、マイグレーション、ストレージ、ポートを読み取り専用で検査し、秘密値は表示しません。起動スクリプトは doctor を再確認して web と worker を起動し、`Ctrl-C` で両方を停止します。

フィルター付きインストール後、通常の `pnpm lint` やコミットに使う各ターミナルで `SAAS_STARTER_PROFILE=core` を export し、同じ構成で検査します。ここでの `export` は POSIX shell 用です。PowerShell では `$env:SAAS_STARTER_PROFILE="core"` を使います。

## 3. 最初の動作画面を確認する

1. `demo@example.test` と `DemoPass123!`、または seed 前に `DEV_SEED_PASSWORD` で設定したパスワードでログインします。
2. **アカウント → クレジット**を開きます。新規環境のデモワークスペースには **1,000 クレジット**と対応する台帳記録があります。
3. **アカウント → プロフィールとセキュリティ**で設定を確認します。ワークスペースとセッションは実際のローカルアプリで動作しています。

この認証情報はローカル開発専用です。Seed は予約済みドメインの検証済みアカウントを作り、同じクレジット付与を重複させずに不足データを修復します。メール送信は不要です。既存のデモ操作により表示残高が変わることがあります。

別のターミナルでサービスを確認します。

```bash
curl http://localhost:3000/api/health
curl http://localhost:3000/api/ready
pnpm test:fast
```

開発と本番ビルドは `.next` を共有するため、ビルド前に `Ctrl-C` で開発プロセスを停止します。

```bash
pnpm starter core build
```

ビルドはルートのテストを維持し、worker ランタイムもまとめます。実際のローカルストレージとモックプロバイダーのジョブを使うブラウザ検証は、使い捨て環境向けの[テストと CI](/ja/docs/testing-and-ci)を参照してください。

## 4. 自分の製品にする

`pnpm customize` で製品情報、外観、言語を設定します。[製品のカスタマイズ](/ja/docs/customize-your-product)と[アーキテクチャとエラー契約](/ja/docs/architecture-and-errors)へ進んでください。外部サービスは該当機能を使う段階で設定します。[環境設定](/ja/docs/environment-configuration)を参照してください。

## 必要なアプリを追加する

プロファイル変更前に現在の開発プロセスを停止します。`http://localhost:3001` の管理コンソールを追加するには：

```bash
export SAAS_STARTER_PROFILE=operations
pnpm starter operations install
pnpm starter operations setup
pnpm starter operations dev
```

運用者権限と MFA は[管理コンソール設定](/ja/docs/admin-console-setup)に従ってください。デモ顧客は自動的に管理者にはなりません。

`http://localhost:3002/admin` の Content Studio も追加するには：

```bash
export SAAS_STARTER_PROFILE=publishing
pnpm starter publishing install
pnpm starter publishing setup
pnpm starter publishing dev
```

Publishing は独立した Payload DB とマイグレーションを準備します。認証と DB は SaaS と分離してください。[Content Studio とマーケティング](/ja/docs/content-studio-and-marketing)で説明しています。

全プロファイルで `doctor`、`lint`、`build`、`--dry-run` を利用できます。プロファイル未選択なら、`pnpm setup`、`pnpm dev:all`、`pnpm build` は全アプリ構成を維持します。対話型の全体セットアップには、`SAAS_STARTER_PROFILE` を設定していない shell で `./scripts/setup.sh development` を使います。

## ローカルデータのリセットは確認して行う

```bash
pnpm dev:reset -- --dry-run
pnpm dev:reset
```

先に対象を確認します。Reset は外部サービスを拒否し、明示的な確認を求め、この Compose プロジェクトのローカルデータだけを再作成します。マイグレーションと、指定がなければ seed を再実行します。環境ファイルは保持します。通常の再起動には不要です。
