完了すると、顧客 app、admin console、Content Studio、durable worker、SaaS dev/test DB、Payload DB、Redis、private S3-compatible bucket が一緒に動きます。

## 必要環境

- Node.js `>=24.22.1 <25`
- pnpm `10.22.0`
- Docker Compose

## ガイド付き初回起動

```bash
git clone https://github.com/PansaLegrand/sushi-saas-template.git
cd sushi-saas-template
pnpm install
./scripts/setup.sh development
pnpm dev:doctor
pnpm dev:all
```

Setup は `pnpm customize` を開き、不足する ignored env を書き、PostgreSQL・Redis・Garage を起動し、`sushi_dev`、`sushi_test`、`sushi_content`、restore DB を作り、Drizzle/Payload migration と `sushi-dev` bucket を準備します。再実行可能で既存 env は上書きしません。中立設定のままなら `pnpm setup` を使えます。

`dev:doctor` は version、環境境界と権限、Docker、DB、Redis、migration、object storage、Studio、port を secret を表示せず読み取り確認します。

`dev:all` は次を起動します。

| Process | Address |
| --- | --- |
| 顧客 app | `http://localhost:3000` |
| Admin | `http://localhost:3001` |
| Content Studio | `http://localhost:3002/admin` |
| Worker | prefix log 付き background process |

## 安全な fixture と reset

```bash
pnpm dev:seed
pnpm dev:reset -- --dry-run
pnpm dev:reset
```

Seed は verified `.test` account、personal organization、deterministic 1,000 credits、demo reservation を冪等に作成・修復します。Reset は外部 service を拒否し、対象を表示して確認を要求し、この Compose project の data だけを再作成します。

## 完全な検証

```bash
curl http://localhost:3000/api/health
curl http://localhost:3000/api/ready
pnpm test:fast
pnpm test:e2e
pnpm build
```

Playwright は Better Auth で login し、tenant credits、実 Garage upload、5-credit image task から worker と signed result までを確認します。次に[製品のカスタマイズ](/ja/docs/customize-your-product)、[アーキテクチャ](/ja/docs/architecture-and-errors)、[テストと CI](/ja/docs/testing-and-ci)へ進んでください。

## 小さな構成から始める

`pnpm starter core install`、`pnpm starter core setup`、`pnpm starter core doctor`、`pnpm starter core dev` は web と worker を対象とします。`operations` は admin、`publishing` は Content Studio も追加します。`lint`、`build`、`--dry-run` も利用できます。Core/operations は Studio の環境作成と移行を省略します。フィルター付きインストール後は `SAAS_STARTER_PROFILE=core` または `operations` をシェルに設定し、lint と pre-commit に同じ構成を使わせます。既定は全体構成で、実行時権限や料金プランは変えません。

初期化時は TCP で PostgreSQL の準備を待つため、一時初期化サーバーが最終起動前に移行処理を開始させることはありません。
