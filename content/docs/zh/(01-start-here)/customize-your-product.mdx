完成本页后，启动模板将以**你的产品**的名称、URL、语言与视觉风格运行；每个可选系统也会有明确的保留、调整或移除结论。请在修改单个页面前完成这些决定，因为产品身份和边界会影响 URL、邮件、法律文本、分析、计费与管理控制台。

## 已提供的能力与需要你的选择

| 范围 | 默认行为 | 你的决定 |
| --- | --- | --- |
| 产品身份 | `saas.config.json` 跟踪名称、slug、支持方式和文档 URL | 运行 customizer 并审核跟踪差异 |
| 支持方式 | 支持邮箱是明确的跟踪产品值 | 上线前设置真实支持邮箱；生产配置门禁要求该值 |
| 语言 | 可用英语、中文、西班牙语、法语与日语；URL 按需添加语言前缀 | 选择默认语言、启用集合与浏览器语言检测 |
| 视觉风格 | `studio` 是 Web 与管理端共享的构建时预设 | 保留它，或在代码中选择 `glass`、`soft`、`editorial`、`brutalist` |
| 颜色模式 | 用户端通过环境变量默认使用 `system` | 选择 `system`、`light` 或 `dark`；管理端尚无模式切换器 |
| 法律页面 | 提供与默认数据流相符、会显示草稿警告的文本骨架 | 填写身份和政策决定，并交由法律专业人士审核 |
| 可选系统 | 计费、存储、邮件、Slack、分析、推荐、任务和预约已有代码或适配器 | 明确保留并配置、调整，或连同 UI、校验、路由与文档一起移除 |

## 建议的起点

先使用真实产品名；在信息架构稳定前保留 `system` 颜色模式与 `studio` 预设；只启用团队能持续维护的语言。在你具备明确用途、用户文案与运营流程前，建议关闭分析、广告、推荐计划和演示功能。

其他选择并非错误，但会增加责任。更多语言意味着更大市场，也意味着长期翻译维护；更鲜明的预设有助于区分产品，却需要完整检查亮色、暗色与管理端；启用现有集成比从零开发快，但会新增凭据、故障模式、隐私披露和支持工作。

## 设置产品身份与语言行为

先运行可跟踪的产品 customizer：

```bash
pnpm customize

pnpm customize -- --name "Acme Cloud" --slug acme-cloud --preset glass --locales zh,en --default-locale zh --support-email support@example.com --docs-url https://docs.example.com --yes
```

命令会验证并原子写入 `saas.config.json`，并只同步现有忽略环境文件中的公开身份值，不会触碰密钥。`--dry-run` 只输出候选内容，`--no-env` 不同步环境。生产门禁会拒绝与跟踪身份冲突的覆盖值。

## 选择一个视觉预设

通过 customizer 选择 preset，或修改跟踪配置：

```json
{ "appearance": { "preset": "glass" } }
```

`src/config/style.ts` 从 `saas.config.json` 派生类型值，Web 与 Admin 使用同一 preset。这是构建时选择，不是用户级选择器。

## 完成法律身份配置

在 `saas.config.json` 的 `legal` 中填写注册实体、地址、隐私与法律联系邮箱、适用法律和生效日期。`src/config/legal.ts` 读取这些值；只有产品专属政策文本与 `LegalData.subProcessors` 在该文件中修改。必填身份字段未完成时，`LegalConfig.isConfigured` 仍为 false，法律页面会显示草稿提示。上线前应同时审查身份信息与具体政策。

内置文本只是起草骨架，不是法律建议或可直接发布的政策。删除未使用的供应商，补充接收个人数据的供应商，让数据保留承诺与账号删除行为一致，并请合格的法律专业人士审核。

## 明确产品边界

对每个可选系统记录一种决定：

1. **保留：**配置凭据、用户文案、监控、故障处理与负责人。
2. **调整：**在现有服务边界后更换政策或供应商，并同步更新测试和公开说明。
3. **移除：**在同一次修改中移除路由、UI、生产校验、任务与文档。空凭据不等于产品决定。

对保留的系统，继续阅读[套餐与权益](/zh/docs/plans-and-entitlements)、[Stripe 计费](/zh/docs/stripe-setup)、[文件上传](/zh/docs/storage-uploads)、[统计与同意](/zh/docs/analytics-and-consent)和[部署与安全](/zh/docs/deployment-and-security)。

## 在开发业务功能前验证

```bash
pnpm config:check
pnpm config:check:prod
pnpm lint
pnpm test:run
pnpm build:web
pnpm build:admin
```

然后确认默认语言没有前缀、每个非默认语言都可访问、语言选择器不会出现已禁用语言、文档与支持链接兑现了承诺、两个应用使用同一视觉预设，以及用户端的亮色/暗色模式都可读。打开隐私政策和服务条款：只要草稿警告或政策占位符仍存在，就不应公开发布。

## 尚未替你完成的部分

`pnpm customize` 已提供可跟踪的品牌与产品配置流程。运行时预设选择、管理端暗色模式、通过环境变量设置支持邮箱、经审核的法律政策，以及可选业务系统的取舍，仍由采用者完成。支持邮箱来自 `saas.config.json` 的 `product.supportEmail`。
