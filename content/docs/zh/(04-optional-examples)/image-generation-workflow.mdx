图像生成是 starter 中最小但完整的生产级付费工作流示例。本地提供器生成 SVG，不调用商业模型；关键价值是它周围的链路。每个被接受的请求固定消耗组织共享的五积分。

```dotenv
ENABLE_DEMO_FEATURES=true
ENABLE_IMAGE_GENERATION_MOCK=true
IMAGE_GENERATION_MOCK_FAILURES=0
```

运行 `pnpm dev:all`，使用演示账户登录并打开 `/zh/tasks/image-generation`。UI 使用一个幂等键提交，并轮询组织范围内的任务状态。

## 可恢复链路

1. API 检查同源、限流和认证；服务先识别重放，再对新操作检查套餐权限。
2. `(user_uuid, type, idempotency_key)` 标识任务，请求指纹拒绝用同一键提交其他提示词。
3. `task_image:<task uuid>` 标识五积分消耗，并发重放只返回已有逻辑借记。
4. 配额预留、五积分扣除、任务及 `task_image_generation:<task uuid>` 派发在同一事务中提交。队列写入失败会回滚扣费。
5. Worker 用稳定 UUID 调用提供器，写入确定性的私有 Garage/S3 对象，验证后激活文件并完成任务。
6. 任务查询只在组织范围解析文件，并返回短时签名 URL；凭据和对象键不会进入公开任务契约。

成功受理的任务返回 `queued`。维护流程在五分钟后修复已扣费的历史任务，无需浏览器重放；维护流程不会为未付款草稿扣费。

```text
queued → running → succeeded
           ↘ refunding → failed
```

提供器最多尝试五次，任务共允许八次，剩余三次专门用于在数据库故障后完成补偿。最终失败先进入 `refunding`、追加确定性的账本退款，再标记 `failed`。重放不会重复运行提供器或退款。

设置 `IMAGE_GENERATION_MOCK_FAILURES=5` 可测试重试与补偿。真实数据库测试证明只有一次消耗和一次退款；Playwright 证明请求重放、精确五积分变化、Worker、Garage 存储和签名下载。

在 `src/services/ai/image.ts` 实现真实提供器，保留传入的幂等键、AbortSignal，以及任务、积分、Worker、存储和错误契约。提供器凭据与 SDK 类型仍留在适配器内。

只替换适配器不会开启生产生成。页面、API 路由和任务服务都检查 `isImageGenerationMockEnabled()`，它在生产始终为 false。需要把这些演示准入检查替换为明确的生产功能配置，同时保留原有的同源、认证、套餐、配额和积分检查。

当前 `GeneratedImage` 类型只允许 `image/svg+xml`、扩展名 `svg` 和提供器 `mock`。接入真实提供器前，应定义并校验允许的输出类型、扩展名、提供器标识与匹配的文件元数据，并测试生产准入、重试、私有交付和补偿。
