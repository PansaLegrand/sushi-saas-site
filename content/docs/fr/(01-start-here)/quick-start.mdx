> Vérifié avec le commit [`323fbf1`](https://github.com/PansaLegrand/sushi-saas-template/tree/323fbf1aedadb57ac9efad1f1f9cc51b6599aa6e).

À la fin, l’app client, la console admin, Content Studio, le worker durable, les bases SaaS dev/test, la base Payload, Redis et un bucket S3 local privé fonctionneront ensemble.

## Prérequis

- Node.js `>=24.22.1 <25`
- pnpm `10.22.0`
- Docker Compose

## Première exécution guidée

```bash
git clone https://github.com/PansaLegrand/sushi-saas-template.git
cd sushi-saas-template
pnpm install
./scripts/setup.sh development
pnpm dev:doctor
pnpm dev:all
```

Le setup ouvre `pnpm customize`, écrit les profils ignorés manquants, lance PostgreSQL, Redis et Garage, crée `sushi_dev`, `sushi_test`, `sushi_content` et la base de restauration, applique les migrations Drizzle/Payload et prépare le bucket `sushi-dev`. Il est idempotent et ne remplace jamais un fichier existant. Utilisez `pnpm setup` pour conserver les valeurs neutres.

`dev:doctor` vérifie en lecture seule versions, limites et permissions d’environnement, Docker, bases, Redis, migrations, objets, Studio et ports sans afficher de secret.

`dev:all` lance :

| Processus | Adresse |
| --- | --- |
| App client | `http://localhost:3000` |
| Admin | `http://localhost:3001` |
| Content Studio | `http://localhost:3002/admin` |
| Worker | processus de fond avec logs préfixés |

## Fixtures et reset sûrs

```bash
pnpm dev:seed
pnpm dev:reset -- --dry-run
pnpm dev:reset
```

Seed crée ou répare de façon idempotente un compte `.test` vérifié, son organisation, 1 000 crédits déterministes et une réservation démo. Reset refuse les services externes, affiche ses cibles, exige une confirmation et ne recrée que les données de ce projet Compose.

## Vérifier

```bash
curl http://localhost:3000/api/health
curl http://localhost:3000/api/ready
pnpm test:fast
pnpm test:e2e
pnpm build
```

Playwright se connecte avec Better Auth et teste crédits tenant, upload Garage réel et tâche image à cinq crédits jusqu’au worker et au résultat signé.
